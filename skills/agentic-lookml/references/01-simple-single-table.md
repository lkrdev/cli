# Simple single-table queries (`simple_single_table`)

Single-table queries without joins, CTEs, unions, or window functions map to `bronze/:table.view.lkml` (autogenerated) + on-demand `bronze/:table.refinement.lkml` + `bronze/explores/:table.explore.lkml` (`hidden: no` until promoted to Silver; Tier 1 auto-apply).

## Tool categorization rule (`lkr parse`)

The parser tags a query with `simple_single_table` when `parsed_query` meets all of these conditions:

- `len(parsed_query.tables) == 1` (a single physical table).
- `parsed_query.joins == []` (no `JOIN` or `UNNEST` joins).
- `parsed_query.ctes == []` and no nested `FROM (SELECT ...)` subqueries.
- `parsed_query.statement_type == "SELECT"` (no `UNION`).
- Every `col` in `parsed_query.columns` has `col.sql` containing only direct columns, simple scalar functions (`DATE_TRUNC`, `COALESCE`), or standard single-pass aggregations (`col.is_agg == True` with `COUNT`, `COUNT(DISTINCT ...)`, `SUM`, `AVG`, `MIN`, `MAX`, and no nested `CASE` or window functions).

## Representative SQL

```sql
SELECT
  status,
  DATE_TRUNC(created_at, MONTH) AS created_month,
  COUNT(*) AS row_count,
  SUM(sale_price) AS total_revenue
FROM `project.dataset.orders`
WHERE created_at >= '2026-01-01'
GROUP BY 1, 2
```

## How to handle

1. **Bronze base view (`bronze/:table.view.lkml`):** Inspect `queries[].parsed_query.tables` and `queries[].views` in `lkr parse sql-lookml-compare`. Only invoke [generate-view-from-table](../../generate-view-from-table/SKILL.md) when a table is missing from `views` or `views[].unmodeled_db_columns` is non-empty. Never hand-edit `bronze/:table.view.lkml`.
2. **Bronze refinement (`bronze/:table.refinement.lkml`, on-demand only):** Create only when adding primary keys, single-table dimensions/Business Terms (`yesno` if boolean-like with `is_<term>` + noun `label: "<Term>"`, or noun `<term>` for categorical/scalar/duration terms; see [SKILL.md](../SKILL.md#triage-query-layer-vs-lookml)) or measures (`sum`, `average`, `count_distinct`, `percentile`, `median`, filtered KPIs, ratios) whose entire `${...}` DAG stays within `:table`, `hidden: yes` / `suggestable: no` governance, or labels/descriptions/synonyms. Whenever the query uses aggregates or scalar wrappers (`ROUND`, `* 100`, `COALESCE`, `COUNT(*)`, `EXTRACT`), evaluate them per [measures-and-sql-functions.md](measures-and-sql-functions.md).
3. **Explore placement (`bronze/explores/` vs `silver/explores/`):**
   - **Existing Silver Explore (`silver/explores/:table.explore.lkml` with `view_name: :table`):** Serve the query and add Quick Start `query:` blocks there (keeping `bronze/explores/:table_base.explore.lkml` `hidden: yes`). Never route a standalone `FROM :entity` query (`FROM users`) onto a fact `LEFT JOIN` explore (`FROM order_items LEFT JOIN users`), which drops 0-activity entities.
   - **Unjoined single-table query (no Silver explore yet):** Serve directly from `bronze/explores/:table.explore.lkml` (`explore: :table`, `hidden: no`, `label: "..."`, `view_name: :table`, plus Quick Start `query:` blocks) and test in `tests/bronze/:table.test.lkml` (`explore_source: :table`). Never create a joinless pass-through Silver explore.
   - **Detaching to Silver when a join is needed:** Only when `:table` requires a cross-table `join:`, `silver/*_fields.view.lkml` bare join, or Silver NDT/SDT, detach into `bronze/explores/:table_base.explore.lkml` (`explore: :table_base`, `hidden: yes`, `view_name: :table`, updating **only `include:`** in `tests/bronze/:table.test.lkml` to `../../silver/explores/:table.explore.lkml` so existing `explore_source: :table` blocks and `tests.snap.json.md` remain untouched) and create `silver/explores/:table.explore.lkml` (`explore: :table`, `extends: [:table_base]`, `hidden: no`, `label: "..."`, `view_name: :table`).

## LookML template (single-table measures in Bronze refinement)

```lookml
# File: bronze/orders.refinement.lkml
include: "orders.view.lkml"

view: +orders {
  measure: total_revenue {
    type: sum
    sql: ${sale_price} ;;
    value_format_name: usd
    description: "Sum of order sale price."
  }
}
```
