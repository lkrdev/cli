# Instructions

> **Scope note:** Authoring or modifying `drill_fields:` is **out of scope for now**. Do not add unrequested `drill_fields:` to measures (or create drill-only `set:` blocks), and do not flag missing `drill_fields:` during reviews.

## 1. Core Standards

1.  **Naming Convention**: Use `snake_case` for all measure names. Normalize quirky or colloquial SQL `AS` aliases (`unique_chaotic_sessions`, `distinct_clicking_humans`) into canonical domain identifiers (`unique_sessions` / `session_count`, `distinct_users` / `user_count`), preserving persona wording in `label:` / `description:`.
    -   **Counts & Distinct Counts**: Prefix with `count_` / `unique_` / `distinct_` or suffix with `_count` (e.g., `count_orders`, `unique_sessions`, `user_count`), or refine autogenerated `count` in `bronze/:table.refinement.lkml`. Never end a `count` or `count_distinct` measure name in `id`, `year`, or `decade` (`unique_session_id`), which suppresses Looker's default thousands-separator commas.
    -   **Sums**: Prefix with `total_` (e.g., `total_revenue`) unless domain KPI terminology dictates a canonical name.
    -   **Averages**: Prefix with `avg_` (e.g., `avg_order_value`).
    -   **Ratios**: Use descriptive names (e.g., `orders_per_user`).
2.  **Required Parameters**:
    -   `type`: `count`, `sum`, `average`, `count_distinct`, `number`, `min`, `max`.
    -   `description`: **Required**. Explain the calculation logic.
    -   *(Out of scope)* `drill_fields`: **Out of scope for now**—omit unless explicitly requested by the user.
3.  **Formatting**:
    -   Use `value_format_name` (e.g., `usd_0`, `usd`, `decimal_2`, `percent_2`) instead of SQL `ROUND(...)` formatting.
    -   `type: count` and `type: count_distinct` share identical default comma formatting across UI tables, tiles, and formatted CSV/TXT/HTML/Markdown exports unless the field name ends in `id`, `year`, or `decade`. Skip blanket `value_format_name: decimal_0` on non-`*id` count measures unless explicit `.xlsx` `#,##0` formatting or a legitimate `*(id|year|decade)` name requires it (in which case apply `decimal_0` equally to `count` and `count_distinct`).

## 2. Common Types

-   **count**: Counts rows. Does NOT need a `sql` param (uses the table's
    primary key; cannot be overridden via the sql parameter).
-   **count_distinct**: Counts unique values. Requires `sql` param.
-   **sum**: Sums a numeric field. Requires `sql`.
-   **average**: Averages a numeric field. Requires `sql`.
-   **number**: For calculations involving other measures (e.g., margins, ratios).

# Examples

## Basic Measures

```lookml
measure: count {
  type: count
  description: "Total number of orders."
}

measure: total_revenue {
  type: sum
  sql: ${sale_price} ;;
  value_format_name: usd
  description: "Sum of all sales prices."
}
```

## Filtered Measure

```lookml
measure: total_revenue_completed {
  type: sum
  sql: ${sale_price} ;;
  filters: [status: "complete"]
  value_format_name: usd
  description: "Total revenue from completed orders only."
}
```

## Measure with Distinct Count

```lookml
measure: count_users {
  type: count_distinct
  sql: ${user_id} ;;
  description: "Number of unique users who placed an order."
}
```
