# Agentic LookML & Looker Skills (`skills/`)

Installable `SKILL.md` packages for automating LookML engineering, validation, curation, and Looker SDK operations at scale with **the LLM and coding-agent harness of your choosing** (Antigravity, Claude Code, Codex, Cursor, GitHub Copilot, or headless CI/ADK pipelines).

Every skill pairs model-agnostic instructions with deterministic `lkr` CLI and Monty sandbox primitives (`lkr parse`, `lkr schema`, `lkr tools lookml`, `lkr code-mode sandbox`) so correctness is enforced by static AST checks, warehouse execution, data tests, and snapshot gates rather than model-specific behavior.

## Quick Install

```bash
# Install the end-to-end LookML workflow and core modeling skills
npx skills add lkrdev/cli --skill agentic-lookml-workflow
npx skills add lkrdev/cli --skill agentic-lookml

# Or install individual skills on demand
npx skills add lkrdev/cli --skill lkr-code-mode
npx skills add lkrdev/cli --skill lkr-project-helper
npx skills add lkrdev/cli --skill generate-view-from-table
npx skills add lkrdev/cli --skill lookml-field-curation
npx skills add lkrdev/cli --skill looker-field-profiler
```

## Three Core Use Cases for Automating LookML at Scale

### 1. SQL Query Workloads at Scale (`1..N` Queries)
Refactor ad-hoc warehouse SQL, legacy reporting queries, or query-log corpora into governed Medallion LookML (`bronze/`, `silver/`, `gold/`):
- **Cluster & deduplicate at scale:** `lkr parse sql-group` groups large SQL corpora by structural AST similarity, summing frequency and scoring complexity before batch refactoring.
- **Deterministic LookML grounding:** `lkr parse sql-lookml-compare` maps SQL tables, joins, projections, and `unmodeled_db_columns` to existing LookML views, fields, explores, and `.test.lkml` coverage offline.
- **Row-set parity gate:** [`agentic-lookml-workflow`](./agentic-lookml-workflow/SKILL.md) (`pre_gate.py`) runs both the original SQL in Looker SQL Runner (`/sql/:id`) and the modeled Explore query (`/x/:id`), proving exact row-set parity (`parity_status: "matched"`) before opening a PR.

### 2. Arbitrary User Instructions, Business Specs (`metrics.md`), & BI Migrations
Author or extend LookML from natural-language prompts, metric/term glossaries, or external BI formulas (such as Tableau calculated fields, LOD expressions, and parameters) with **zero raw SQL required**:
- **Offline semantic grounding:** `lkr schema context -m <model> --path <dir> --prompt "<instructions>"` ranks matching Explores, joins, views, dimensions, measures, and `candidate_merge_keys` via local BM25; `lkr parse lookml-database-compare` identifies unmodeled warehouse tables and columns (`unmodeled_in_lookml`).
- **Unified Medallion & BI pattern mapping:** [`agentic-lookml`](./agentic-lookml/SKILL.md) applies the same Canonical Looker Query gate, Bronze/Silver/Gold rules, and Triage playbooks (e.g., Fixed LOD cohorts $\rightarrow$ ephemeral Silver Rollup NDTs; window calculations $\rightarrow$ Table Calculations or `derived_column:`; runtime parameters $\rightarrow$ Gold `always_filter:` explores).
- **Live Explore verification:** When no SQL baseline exists, `pre_gate.py` registers `/x/:id` Explore queries from `inline_queries.json`, executes them live against Looker and the warehouse (`parity_status: "verified"`), and captures immutable test-slice baselines (`test_queries_json`).

### 3. Database Schemas, Curation, & Warehouse Governance at Scale
Bootstrap greenfield LookML projects, synchronize warehouse schema evolution, and mirror cloud data governance automatically:
- **Greenfield & schema-wide Bronze generation:** [`lkr-project-helper`](./lkr-project-helper/SKILL.md) and [`generate-view-from-table`](./generate-view-from-table/SKILL.md) (`lkr tools lookml create --match "<schema>.*" --folder bronze`) generate 1:1 `# AUTOGENERATED` physical views on demand or continuously from BigQuery Cloud Logging webhooks (`--event-json` / `--port`).
- **BigQuery security mirroring (`--bq-security`):** Mirrors BigQuery Table IAM, Row Access Policies, Policy Tags, and Dynamic Data Masking into `security/*.refinement.lkml` and Looker User Attributes on Service Account connections so PDTs and `aggregate_table` rollups stay governed.
- **Automated profiling & semantic curation:** [`looker-field-profiler`](./looker-field-profiler/SKILL.md) (`profile_fields`) and [`lookml-field-curation`](./lookml-field-curation/SKILL.md) (`lkr parse curation-meta`) classify cardinality/spikiness and populate `description:`, semantic `tags:`, `hidden:`, and `suggestable:` in `bronze/:table.refinement.lkml` for human analysts and Conversational Analytics agents.

## Deterministic Verification & CI Governance

Every automated run passes through four model-independent gates (packaged for GitHub Actions in [`lookml-pr-checks.yml`](./agentic-lookml-workflow/examples/lookml-pr-checks.yml)):
1. **Static AST & Query Schema Gate (offline):** `lkr parse lookml-to-api --validate` catches duplicate field logic, alias collisions, invalid `value_format_name`, raw `STDDEV`/`PERCENTILE` in `type: number`, raw SQL table names in `derived_table.sql`, and unpropagated RLS; `lkr schema validate` checks `WriteQuery` payloads and `dynamic_fields` formulas.
2. **Looker Project Validator & Warehouse Execution (`pre_gate.py`):** Runs `validate_project` in `--dev` mode and verifies either SQL Runner parity (`matched`) or live Explore execution (`verified`).
3. **Bounded LookML Data Tests (`.test.lkml`):** [`validate_and_commit_branch.py`](./agentic-lookml-workflow/scripts/validate_and_commit_branch.py) and [`diff_lookml_tests.py`](./agentic-lookml-workflow/scripts/diff_lookml_tests.py) execute only newly added or modified `test:` blocks on immutable historical slices.
4. **Additive vs. Breaking Snapshot Gate (`lkr parse lookml snapshot --allow-additions`):** Purely additive LookML PRs (`requires_review: false`) pass CI automatically without human bottlenecks, while material modifications to existing measures, SDT SQL, tests, connections, or PII/access controls automatically request `CODEOWNERS` approval.
